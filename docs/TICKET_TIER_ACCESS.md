# Staging ticket-tier access

This experiment is enabled only at staging.openanonymity.ai. Production is not released by this change. It changes no picker or composer UI. Selecting a model never spends tickets. Before a request, an eligible unexpired key is reused. Otherwise the existing acquisition flow purchases a fresh key at the full selected tier price with its full allowance and duration. Higher-tier keys cover the explicitly listed equal/cheaper models. Prior paid keys remain available in this chat until expiry; Parallel lanes retain their own purchases. Exhausted, rejected or banned access cannot be restored.

The org receives only tickets, never the selected model ID. With its local rollout marker enabled, it derives an immutable allowed-model list from the same pricing map, freezes that list in the downstream retry binding, and signs its hash in OrgAuth. The station attaches a key-specific OpenRouter guardrail before returning a new credential. No shared account defaults are modified. The response supplies the purchased list for client reuse decisions. Live pricing must explicitly contain a model before redemption; fallback display prices cannot authorize a purchase.

A Web Lock serializes acquisition per chat across tabs. Stored access is merged before balance checks and again under the lock. IndexedDB saves merge retained purchases and retirement tombstones. Background verifier outcomes update retained keys as well as active keys. Histories are local credentials and follow the same storage protections as existing active keys; no account joins or new analytics are introduced.

Existing unrestricted keys remain usable according to recorded ticket count in the new client until expiry. Older tabs require reload and are not evidence of provider enforcement on legacy keys. Server policy rollback must preserve pending signed-policy requests, and client rollback must allow feature-key guardrails to expire or remove only this experiment's assignments; do not revoke purchases, reset wallets or edit account-wide guardrails. Deployment evidence and exact rollback live in oa_family/deployment/tier-key-staging-20261104/HANDOFF.md.

Tests cover tier eligibility, retained keys, cross-tab purchase reuse, rejection retirement, Parallel/Quick Ask restoration, and ordinary verifier/access controller regressions. Backend fixtures cover policy binding, station confirmation, assignment failures, cleanup ambiguity, and replay. Deployment checks must separately establish provider enforcement and actual browser behavior. Source includes the existing staging timing experiment and must not be promoted wholesale to production.
